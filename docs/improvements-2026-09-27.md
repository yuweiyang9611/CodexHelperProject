# 查询、导出与宿主完善记录

日期：2026-09-27。保持版本 0.6.0；本轮没有发布安装包。

## 行为与维护约定

- `DashboardService` 按工具缓存当前读取轮次的分析数据；同一轮筛选不再次进入日志／账本读取。每个工具只保留最后一个筛选的聚合结果，分页只生成当前页会话，不累积历史筛选缓存。
- `LoadAsync` 开始即使分析缓存失效，读取失败不会继续返回上一轮缓存。索引重建显式清缓存；相关设置、清理与恢复通过替换读取服务失效。外部日志变化在下一次手动／自动刷新后可见。独立使用 `QueryUsageAsync` 的调用方需要遵循相同刷新约定。
- 查询期间若缓存被作废，旧读取不得写回；失败与取消不缓存。前端保留一个进行中查询及一个最新待执行条件，跳过连续筛选中的中间条件；旧结果、旧错误与已卸载视图的结果均不回写。
- 可用 Token 字段交集使用逐步集合运算，避免每条历史贡献嵌套一层延迟迭代器；会话标题查找使用字典，避免当前页每组再次扫描全部历史。
- 当前筛选导出覆盖所有匹配用量，分页不会改变报表分母。JSON schema 3 包含 `filters` 和全部匹配记录的 `appliedRates`，不是仅当前页的费率。项目保留末级名称并标明完整路径已省略。
- 筛选 CSV 使用 `record_type`：一行 `metadata` 保存 `selection_json` 和 `applied_rates_json`，后续 `day` 行保存每日统计；嵌套 JSON 按 CSV 引号规则转义，可包含换行。空范围也保留 metadata。原设置页全部历史 CSV 的六列布局不变，JSON 继续 schema 2，并增加实际适用费率信息。
- 未知金额保留 null／空白，旧整日估值继续单列，不与明细金额相加；报表不导出会话 ID、标题、完整项目路径或诊断文本。
- `ShutdownCoordinator` 统一管理退出状态、Sidecar 关闭、退出时更新安装和维护确认。关闭到托盘不进入退出；维护与非零退出不安装更新。更新安装抛错也会释放退出屏障并保留非零退出码，不留下未处理的 Promise。
- Electron README 和历史文档明确旧桌面副本已退役；WPF 继续参与构建并作为兼容参考。新的原生验收清单只覆盖仍在使用的窗口、托盘和状态条。

## 合成性能样本

使用固定日期、10,000 条贡献、每会话 10 条贡献、每页 25 组，首次查询预热后连续查询 10 页。前后使用相同数据和工具链，checksum 均为 10,000,000；不读取真实用户日志。

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 10 页查询耗时 | 477.54 ms | 9.86 ms |
| 分页阶段累计分配 | 240,543,816 B | 1,612,920 B |
| 含预热的数据读取次数 | 11 | 1 |

以上是单次本机测量，排除首次读取／聚合和文件索引，不是应用启动时间、峰值内存或跨机器性能保证。CI 断言读取次数、聚合复用、失效行为和结果正确性，不设置依赖机器速度的毫秒阈值。

另外以 100,000 条贡献复测，10 页累计分配为 1,612,568 B、读取次数仍为 1、checksum 为 100,000,000；本次耗时 4.62 ms。该时间与前一规模的运行状态不同，不用于推导规模越大越快。

复现：在仓库根目录以 `global.json` 固定的 .NET SDK 运行：

```powershell
dotnet run --project tools/UsageAnalysisBenchmark --configuration Release -- 10000
dotnet run --project tools/UsageAnalysisBenchmark --configuration Release -- 100000
```
