# codexU 产品需求确认稿

确认日期：2026-09-22。状态：用户已确认 Q1–Q20 的最终建议。

本文记录本轮需求访谈达成的产品约定，是后续功能重整与验收的依据，不代表所述能力已经实现或发布。用户随后授权开始实现；合并与发布不属于本次实现操作。旧设计文档继续作为实现背景；与本文冲突的产品方向，以本次确认结果为准。

## 1. 定位与范围

- 面向个人用户的本地桌面工具，以现有 Windows 应用为改造对象。
- 核心目标：看清本机用量花在哪里，包括模型、功能、项目及历史趋势，并能追查到会话贡献。
- 辅助目标：掌握账户额度余量与刷新时间，减少使用中断。
- 参考信息：API 等效金额及可选的订阅月费对比。
- Codex 与 Claude Code 都作为正式支持对象，分别统计、使用统一的查看方式。界面一致不等于两种来源能提供完全相同的数据字段。
- 允许重排页面、删除无用功能或重做现有流程，不以保留旧页面为目标。

本轮不新增团队管理、跨设备云同步、任务管理或对话阅读功能。

## 2. 页面与默认行为

主入口收敛为三个：

| 入口 | 职责 |
| --- | --- |
| 总览 | 当前工具的本机用量概况、账户额度及金额参考；提供可选的两工具并排比较视图。 |
| 用量分析 | 时间趋势、模型与功能分布、项目排行、筛选、会话下钻，以及次级的 Skill 和工具调用分析。 |
| 设置 | 数据来源、通知、费率、订阅月费对比、悬浮条、更新、导出、备份恢复、索引重建与历史清理。 |

- 打开应用时记住上次选择的工具。
- 默认时间范围为近 30 天。
- 工具切换入口清晰可见；并排比较使用同一套指标定义，取消独立的“双运行时”页面。
- 项目排行、Skill 和工具调用归入用量分析，不再各自占据主导航。
- 分析路径为：总览 → 日期／模型／项目筛选 → 会话用量明细。

## 3. 数据口径

### 3.1 本机用量与账户额度

- “本机用量”包含本机可读取及已经留存的全部历史。它不等同于当前账户在所有设备上的总用量，也不假定旧日志能够可靠归属到当前登录账户。
- 账户额度独立展示。筛选日期、模型或项目，不改变账户额度的统计范围。
- 两种工具的额度分别显示，不合成为一个剩余百分比。
- 来源无法提供的额度或字段显示为未知／不可用并说明原因，不根据 Token、限流次数或金额倒推。

### 3.2 Token 与金额

- 趋势、排行和占比默认按原始 Token 展示，可切换为 API 等效金额。
- “原始 Token”是按各来源定义归一化、经过现有去重规则后的本机用量，不按模型价格加权，也不是账户额度消耗比例。
- 可查看输入、缓存、输出分项；明确各来源的包含关系。例如缓存已经计入输入时，不能再与输入相加；来源没有提供的缓存细分或推理分项不得伪造。
- API 等效金额是按模型及适用日期费率折算的参考值，不是订阅扣费或真实 API 账单。
- 所有页面对同一指标使用一致的名称、范围和分母。不同含义的覆盖比例必须说明分母，不能用同一名称表达不同口径。

## 4. 时间范围、筛选与一致性

- 支持今日、近 7 天、近 30 天、本月、全部历史和自定义日期。
- 本轮按天统计，沿用本机日期口径，不提供小时级趋势，也不把旧日桶包装成精确事件时间。
- “全部历史”覆盖已经留存的全部日期，不受当前快照最近 182 天的返回范围限制。
- 日期、模型、项目可以组合筛选；切换模型或项目时保留当前时间范围。
- 当前工具和筛选条件同时作用于总量、趋势、分布、排行、金额与会话列表。账户额度独立于这些筛选。
- 同一统计范围内，可归属明细与未归属部分合计必须等于总量。不能在趋势图保留旧历史分类，却在相同范围的排行中把整天归回未知。

## 5. 会话明细与子代理

会话明细用于解释用量，不恢复任务看板或任务生命周期管理。

| 字段 | 展示约定 |
| --- | --- |
| 标题与 ID | 有可靠标题则显示；没有标题时使用简短 ID。保留可识别会话的标识。 |
| 项目与日期 | 展示来源可以确认的项目和日期；不能确认时说明缺失，不生成虚假的项目或精确时间。 |
| 模型 | 支持同一会话使用多个模型，并能解释模型筛选下的贡献。 |
| Token | 展示当前筛选范围内的用量及来源支持的分项。 |
| 金额 | 展示可计算的 API 等效金额；缺失金额不当作零。 |
| 数据来源状态 | 说明来自当前原始日志、历史留存、旧汇总或存在来源冲突，以及这些状态带来的限制。 |

- 不通过读取对话正文来猜测标题，不新增对话正文浏览或留存需求。
- 主会话默认汇总自身及能够确认属于它的子代理贡献，展开后分别查看。
- 主会话、子代理和汇总视图复用同一套去重后的贡献。展开或折叠不改变总量，不重复计入继承上下文。
- 无法确认父子关系的记录单独展示，不强行归并。
- 只有日汇总的历史不能伪造为某个真实会话；以“未归属历史用量”展示，可查看无法继续下钻的原因。

## 6. 历史回填与留存

- 优先从原始日志补齐模型、功能、项目及会话归属。
- 仅采用能够确认属于同一运行时、日期和工作区范围且无来源冲突的明细。沿用工作区边界和 fork 去重规则。
- 按维度保留已有证据：功能未知不意味着已知模型也必须变为未知。
- 只把剩余无法归属的差额保留为未知；无法确认的改写保留可靠历史并说明冲突，不静默覆盖。
- 已读取历史长期保存在本机，不随原始日志删除而消失。
- 普通刷新或重建索引不得清空已留存历史。
- 设置中保留导出、备份恢复和主动历史清理入口；清理前说明影响。

## 7. API 等效金额与费率

- 保留 API 等效金额及可选的订阅月费对比，去掉“回本倍数”“净收益／净等价值”等把估算表达成实际收益的表述。
- 用户补充或修正费率后，可确认的明细按用量发生日期匹配适用费率并重新计算，能够说明采用的费率。
- 未来生效的费率不用于更早的用量。沿用自定义费率、固定目录和历史费率版本的有效约束。
- 只有旧金额而缺少足够 Token 分项的历史，保留原估值并单独标注；不得将包含某明细的旧估值与该明细的重算金额重复相加。
- 缺失金额与零金额明确区分。费率变化不改变 Token 总量或分类。
- 缺少费率默认在金额模块提示具体模型及适用日期问题；未知模型、未归属历史差额本身不构成“请补充模型费率”的理由。

## 8. 辅助功能与精简

| 功能 | 约定 |
| --- | --- |
| 额度不足、额度刷新通知 | 默认开启，保留通知设置。 |
| 额度耗尽预测、金额阈值通知 | 保留手动开启的开关，默认关闭。 |
| 缺少模型费率 | 默认在金额模块提示，默认不弹系统通知。 |
| 小型额度悬浮条 | 保留且可以关闭，只呈现额度余量与刷新时间；详细分析在主窗口完成。 |
| Skill、工具调用次数 | 保留，降为用量分析中的次级内容；没有可靠日期归属的累计次数不能伪装为所选期间的次数。 |
| 完整桌面副本 | 删除。 |
| 任务生命周期统计 | 删除。 |
| 今日任务、待办与目标 | 继续不提供，不能以会话明细的名义恢复这些管理功能。 |

保留已有 GitHub 自动更新能力，默认接收正式版本。安装版自动下载、校验及安装的现有行为继续遵循 [自动更新设计](automatic-updates.md)，本轮不新增发布或升级操作。

## 9. 验收标准

| 编号 | 场景与通过条件 |
| --- | --- |
| A01 | 两种工具分别使用同一套查看流程；重新打开应用保留上次工具选择，时间范围默认近 30 天。 |
| A02 | 切换日期、模型、项目后，所有用量图表、排行和会话明细对应同一筛选范围，账户额度不受影响。 |
| A03 | 能查询超过 182 天的已留存历史；日桶不可还原精确时间时不显示虚假小时信息。 |
| A04 | 同范围的分类明细合计加未归属部分等于总量，图表与排行一致；部分已知维度不会被其他未知维度抹去。 |
| A05 | 主会话与子代理的去重后贡献相加正确，展开、折叠、重复日志或归档副本不会增加总量；不确定关系单列。 |
| A06 | 会话标题、项目等缺失时有明确替代展示；旧日汇总的差额可解释但不伪造为真实会话。 |
| A07 | 原日志删除后，仍能查看已经留存的历史用量；刷新、重建索引和升级不导致历史静默丢失。 |
| A08 | 输入、缓存、输出的包含关系清楚，分项不重复相加；不可用字段与零值可以区分。 |
| A09 | 修改费率只重算适用的金额，遵守历史生效日期；Token 总量不变，旧估值与明细金额不重复相加，未核算金额不当作零。 |
| A10 | 默认只启用额度不足和额度刷新通知；预测和金额阈值需手动开启，未知历史差额不会触发补费率误报。 |
| A11 | 导航只有总览、用量分析、设置三个主入口；并排比较为总览中的可选视图；删除的任务管理与桌面副本入口不再出现。 |
| A12 | 设置可以导出、备份恢复、重建索引及主动清理；清理有影响说明。正式版本自动更新能力保留。 |

## 10. 实施前的基线差距

以下是访谈期间基于本地代码 `22df6ab` 的核查结论，不是新增需求，也不是完成声明：

- 当前 IPC 主要提供聚合快照，没有完整的任意日期／模型／项目组合查询、会话明细及分页接口。
- 当前快照返回最近 182 天的每日数据，界面分布仅有 7／30 天切换；账本本身保留更多历史。
- 两种来源已保留大量会话级用量；但 Codex 历史 Token 时间主要只到日期，标题依赖当前 SQLite；Claude 用量账本没有标题。缺失数据不能凭空恢复。
- 旧历史分类回填已进入每日分布，但累计模型与项目排行还存在整日未知的处理，需要统一。
- 费率提醒已经排除未知历史差额，但金额卡与提醒的覆盖比例名称和分母仍需明确；新的默认通知行为尚待实现。
- 现有界面仍包含独立项目、Skill、双运行时页面，以及任务生命周期统计、完整桌面副本和回本相关展示，需要按本需求重整。

已有统计与历史实现背景见 [本机 Token 账本](local-token-ledger.md) 和 [历史留存说明](usage-history-and-desktop.md)。后续实现应以本文验收标准验证结果，而不能把现有实现限制当成已经满足的新需求。
