# GitHub 自动更新

Windows x64 Electron 安装版默认每天检查 GitHub Release，后台下载更新，在正常退出时安装。“重启并更新”会立即结束本应用并安装，成功后重新打开；关闭到托盘不算退出。用量数据与设置保留在原来的本机数据目录。

设置中的“每天自动检查更新”控制后台检查；“自动下载并在退出时安装更新”控制下载和退出安装。关闭后仍可手动检查、下载并点击重启更新。切换预发布渠道或关闭自动安装会取消当前下载并撤销待安装状态。预发布版本默认不接收，需要勾选“接收预发布版本”。

ZIP 便携版、开发环境和旧 WPF 宿主不执行自动安装。首次使用此功能需要手动安装包含该功能的版本；此前已经发布的应用无法凭空获得自动更新能力。

## 发布要求

沿用现有 GitHub Release 流程，无需另外维护更新服务器。更新源固定为 `yuweiyang9611/CodexHelperProject`，版本标签使用 `v<version>`，发布完成后必须同时提供：

- `CodexU-<version>-win-x64-setup.exe`
- `CodexU-<version>-win-x64-setup.sha256`，内容为 SHA-256、两个空格和完整安装包文件名。

应用只接受完全匹配的附件名称、标签和下载地址。下载会限制大小、检查完整长度与 SHA-256，并在 GitHub 返回附件 digest 时交叉核对。安装前再次验证缓存文件。API 令牌仅从进程环境变量 `CODEXU_GITHUB_TOKEN` 读取，且只用于固定仓库的 GitHub API 请求，不发送给下载重定向；私有附件不支持自动下载，可通过发布页更新。

## 生命周期与失败处理

Electron 主进程负责调度和下载，因此窗口隐藏时仍能检查更新。检查结果沿用后端的一天缓存；主进程每小时尝试读取，网络失败可以通过手动检查/重试恢复。下载任务合并，设置变化取消过期任务。下载超过 20 分钟会中止，半成品会删除；成功缓存可在下次启动重新验证后复用，仅清理更新目录下本功能命名的旧安装包。

退出时先停止下载，再等待 Sidecar 安全退出。只有正常退出且后端退出成功才启动安装器，维护卸载或异常退出不会触发更新。安装器仍会执行现有维护握手，以处理退出期间新启动的实例；安全退出失败则中止安装。安装参数禁用强制关闭和系统重启，原路径覆盖安装，只有显式“重启并更新”才在安装后重新打开应用。

下载或校验失败不会修改现有安装，界面显示失败并允许重试。安装器启动失败会阻止继续安装；安装阶段失败可查看系统临时目录的 Inno Setup 日志并重新运行官方安装包。本实现不承诺跨版本自动回滚，也不把同源 SHA-256 当作发布者数字签名。

静默安装与启动参数遵循 [Inno Setup 命令行文档](https://jrsoftware.org/ishelp/topic_setupcmdline.htm) 和 [Run 节文档](https://jrsoftware.org/ishelp/topic_runsection.htm)。
