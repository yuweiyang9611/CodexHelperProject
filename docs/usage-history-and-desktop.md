# 用量历史与桌面功能

## 工作区与历史口径

Codex 先合并 active/archive，再移除可验证的 fork 回放，最后过滤工作区。工作区优先取当前会话头部 `cwd`，缺失时只读查询线程 SQLite；回放的父元数据不覆盖子会话。两个运行时共用大小写、末尾分隔符及目录边界规则，`D:\Repo2` 不属于 `D:\Repo`。

工作区同时影响 Token、等效金额、趋势、模型、工具、Skill 和项目；“显示子代理”只影响任务列表。未知归属计入全局，指定工作区时排除并提示。账户额度保持账户级。项目金额直接按本项目每日模型用量计算，未知项目单列。

`%LOCALAPPDATA%\codexU\history\usage-ledger-v2.sqlite` 按运行时和逻辑来源保存规范化贡献，包括工作区、模型、日期、Token 分项、读取位置、完整性和 Codex fork 身份；不保存正文、工具参数或凭据。

- 追加且前缀一致：更新同一来源，不另加一份完整来源。
- 缺失或读取失败：保留上次有效贡献。
- 截断、改写、身份冲突：保留旧版本并标记，不逐字段取最大值，也不叠加两个版本。
- 同日新增独立来源：正常合并；重复刷新和重启不重复计量。
- 保存全部日期，热力图显示最近 182 天；今日、近七天、本月、累计、模型和项目来自同一投影。
- 按发生日期选择模型费率，修改历史费率后重新计价，未来费率不影响旧日期。

每日来源为 `live`、`retained`、`legacy` 或 `conflict`。混合来源优先显示冲突，其次是留存。Dashboard 的 `history` 提供留存、冲突和旧快照数量。

原 `daily-usage-*-v1.jsonl` 保持原样，按旧作用域指纹幂等导入。v1 缺少模型明细，保留采集时点数，不能按模型重新计价。同日不叠加：旧总量更大或缺少新明细时，整日采用旧快照并标记待核对；新明细总量覆盖旧值时采用明细。旧点数仍按当前展示兑换参数转换为美元等效金额。

备份 schema 3 使用 SQLite 一致性快照、SHA-256 清单、完整性与版本检查，继续支持 schema 1/2。恢复失败使用事务检查点回滚；成功后重建读取服务并刷新。备份、恢复、账本写入共享维护锁。索引重建只移走缓存，不删除历史。超出备份容量限制时明确报错，不截断数据。

恢复范围按版本限定：schema 1 只恢复设置和待办；schema 2 恢复旧 JSONL 历史，保留当前 SQLite 账本；schema 3 恢复完整历史快照，包括删除该快照中不存在的历史文件。恢复及回滚都会清除进程内缓存。

## Claude 索引

同一个增量索引设置控制两个运行时。Claude 缓存保存版本、时区、Windows 文件身份、元数据、完整行偏移、已提交前缀指纹和紧凑解析结果。普通刷新时未变化文件不读取 transcript 内容；追加会读取并校验完整旧前缀，然后只解析新增行，避免漏掉日志中部改写。截断、替换或无效缓存重新解析。最后半行不提交，超过 4 MiB 的行按既有规则跳过。缓存失效不删除历史。

两个运行时在进程启动后的首次读取，以及距上次成功完整校验满一小时后的首次刷新，验证全部可读文件的完整前缀。等长改写且保留修改时间的特殊情况可能延迟到此时才被发现；应用关闭或暂停刷新期间不执行校验。校验失败不推进时间，下次刷新重试。工作区及费率切换不重置计时；“安全重建索引”强制重新解析。诊断展示最近完整校验时间及待校验状态。

进程内复用解析索引、账本来源和日期/模型/项目汇总，未变化来源不重复反序列化或写入账本。恢复、回滚、索引重建和应用关闭使缓存失效；首次启动始终从持久化来源重建。冲突、实际读取失败和历史留存分别计数，冲突不会再显示为文件读取失败。

30,000 行合成数据测试断言：未到校验周期的未变化刷新，transcript 内容读取量、解析行数、历史来源反序列化次数及账本写入次数均为零；追加时只解析一条新增完整行，并与全量结果对照。输出分别记录索引阶段及完整刷新耗时、分配字节和工作集；工作集是整个测试进程的采样值，不是单次操作峰值。不设依赖机器速度的 CI 阈值。

## 桌面窗口与安全边界

状态条使用独立沙箱窗口，复用 Core 展示投影及布局尺寸、边距，兼容旧 `status-strip-placement.json` 物理像素位置。Electron 负责 DIP 转换和工作区约束。主窗口隐藏后继续分发快照，Sidecar 只采集一次。

只有用户拖动才记录手动位置；程序调整尺寸和显示器约束不改变定位模式。“找回位置”清除保存文件及备份，恢复自动定位，重启后保持自动模式。锁定阻止用户拖动，但不阻止窗口回到可见范围。

桌面副本使用独立 Electron 进程，只通过私有进程管道接收快照，允许刷新和打开主界面/待办。登记 HWND 只进入专用 .NET 桥接管道，Vue 不能发起原生附着。桥接校验窗口进程归属、探测 Explorer 桌面宿主、切换 WS_POPUP/WS_CHILD、验证实际父窗口并恢复位置。

跨进程 `SetParent` 可能重置子进程 DPI awareness，因此副本和主窗口分属进程，依据 [Microsoft SetParent 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)。附着失败时隐藏副本并报告原因；连接和进程退出都有有限次退避恢复。关闭桌面模式只销毁副本，退出应用清理管道及子进程。

## 验证入口

使用锁定的 .NET SDK 10.0.400、Node 22.23.2 和两套 npm lockfile：

```powershell
./tools/Verify-Environment.ps1
./tools/Verify-Project.ps1 -Install -Desktop -Package
```

`-Dotnet` 可指定独立 SDK；Node/npm 在 PATH 中选择锁定版本。真实桌面测试启动 Electron、preload 和自包含 Sidecar，以临时目录提供合成数据，覆盖设置重启、运行时切换、历史、备份恢复、状态条及后端/renderer 异常。只替代文件选择对话框的选定路径，不使用演示 bridge。

验证脚本支持 PowerShell 7.2，逐条检查原生命令退出码；失败立即停止并返回非零状态。`tools/Test-VerificationFailure.ps1` 在临时工具链中验证依赖安装、测试、构建和打包失败传播，不调用真实安装器。

设置 `CODEXU_RUN_DESKTOP_ATTACH_TEST=1` 可额外验证真实 Explorer 附着；该测试不会重启 Explorer。无交互打包 smoke 不创建状态条或桌面副本，不修改系统设置。

## 专用环境验收

支持目标保持 Windows 10 22H2 / Windows 11；WPF 继续参与解决方案构建，无 Linux 支持或自动稳定版发布。以下需专用虚拟机和一次性用户，不能用当前开发桌面替代：

| 场景 | 要求 |
| --- | --- |
| Win10 22H2 / Win11 启用桌面模式 | 报告真实附着，主窗口独立 |
| 重复 Win+D | 副本留在桌面，不抢焦点 |
| 重启 VM 中 Explorer | 有限次恢复，失败有原因，无进程残留 |
| 100%/150%/200% 混合 DPI、负坐标 | 无越界、错位或主窗口 DPI 污染 |
| 移除副屏、重启、找回 | 状态条和副本恢复可见位置 |
| 安装、v0.5.0 升级、卸载 | `Test-ElectronInstaller.ps1` 通过，保留用户数据 |

Docker 可承担后端和 Web 测试，普通 Windows 容器不提供这些验收需要的交互式桌面。虚拟机矩阵未跑完之前，不把六项全部验收标为完成。本次结果见 [implementation-validation.md](implementation-validation.md)。
