# 用量分析改造与验收记录

日期：2026-09-22。需求依据：[产品需求确认稿](product-requirements.md)。

本次实现位于 `codex/usage-analysis-redesign` 分支。本文记录本地验收结果，GitHub 检查状态以对应合并请求为准。

## 实现结果

- 总览、用量分析、设置三个主入口；记住工具选择，两种工具在相同筛选范围下并排比较。
- 新的 `usage.query` 接口从同一套去重贡献生成全部历史、组合筛选、图表、排行和分页会话组；账户额度保持独立。
- 主会话与确认的子代理按贡献汇总；标题缺失显示 ID；旧汇总差额单列，不伪造会话。
- 日志与账本记录 Token 分项是否实际可用。旧记录可以从原始日志补齐；无法确认的字段显示未知，不把缺失当作零。
- 金额按用量日期和适用费率重算，缺少费率与缺少 Token 分项分别解释；旧整日估值单列且不参与明细加总。
- 可选金额阈值通知也使用本月已核算明细，避免沿用旧估值触发不一致的提醒。
- 默认仅开启额度不足与额度刷新通知，保留可关闭的额度悬浮条；删除任务生命周期和完整桌面副本入口。
- 新版聚合导出覆盖当前工具全部历史，使用同一计算口径；JSON schema 2 保留未知金额与独立旧估值，CSV 未知金额留空。
- 历史清理采用原生确认与可恢复检查点；清理不删除原始日志或设置。刷新、重建索引继续保留已读取历史。

## 验证环境与结果

- 本地 Windows，Node.js 22.23.2。
- 本机安装的是 .NET SDK 10.0.401；从本地验证目录选择该 SDK 执行构建，仓库 `global.json` 的 10.0.400 固定版本未修改。
- 整个解决方案 Release 构建通过，警告视为错误。
- 后端测试：Core 198、Contracts 11、Infrastructure 250、Sidecar 94，共 553 项通过。
- Web 单元测试：183 项通过；Electron 单元测试：113 项通过。
- 浏览器验证覆盖深浅主题、100%／125%／150%／200% DPI、140% 界面缩放和紧凑窗口；按矩阵执行 42 个有效场景，其他组合按既有规则跳过重复的语义检查。新版截图经过查看，变更的基线单独更新和复测。
- 真实 Electron 使用实际 preload、renderer 和已发布到本地的 Sidecar，验证查询、分组、删除日志后的留存、导出、清理取消／确认、备份恢复、Sidecar 与 renderer 崩溃恢复。
- 历史清理、故障注入与真实桌面集成均使用临时合成数据。
- 修改的 C# 文件格式检查及 `git diff --check` 通过。

## 保留的边界

- 不能恢复的旧标题、精确时间、Token 字段及会话归属继续显示未知；不会通过读取正文猜测。
- `usage.getSnapshot` 的旧汇总结构保留兼容行为；新界面和新聚合导出使用 `usage.query`，不受旧快照 182 天范围限制。
- Skill 和工具调用仍作为累计辅助统计，并明确其与日期／模型／项目筛选的区别。
- 设置中的聚合导出明确针对当前工具全部历史，不假称只导出界面当前选择的日期或项目。
- 本轮没有调整正式版本号或发布安装包。
